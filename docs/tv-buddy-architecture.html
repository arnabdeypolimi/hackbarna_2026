TV buddy: planes, control tools, rec tool, memory

Media rides WebRTC across the top and back. Control rides its own socket. The LLM reaches the TV only through the control tools, which resolve what the user meant against the snapshot pinned at VAD onset and refuse anything they cannot resolve.

blocking, inside the turn parallel, non-blocking memory injected into context

Why the control tools are their own box. The control plane is a protocol; the tools are the agent-side layer that decides what to send over it. Deixis resolution, the stale-seq retry policy and the refusal rules all live there, not in the LLM and not on the TV.

Two command classes. Item commands carry a catalog ID, mean the same thing whenever they land, and can be retried against a fresh snapshot. State commands like back and close act on the current screen, are not idempotent, and on conflict hand the refreshed view back for a new decision.

Three stores, kept apart. Catalog and item embeddings never enter memory. Watch history is behavioural and belongs to the CF model. Only stated preference, persona and affect go into VoiceMem, which is exactly the signal collaborative filtering cannot see. View state is per-turn context and reaches neither.
