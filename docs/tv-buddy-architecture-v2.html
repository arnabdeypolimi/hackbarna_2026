TV buddy v2: planes, command bus, tools, memory, and the agent loop

Media rides WebRTC across the top and back. Control rides its own WebSocket. One Pipecat pipeline per session; the agent is a Pipecat LLMService that streams a strict JSON envelope, speaks say sentence by sentence while actions[] dispatch in parallel, and never runs more than two model cycles per turn. Everything that can wait — memory ingest, history writes, status events — is fired and never awaited.

The agent loop, one turn

SGRAgentService._turn: recall, prompt, one streamed cycle, an optional bounded second cycle, close. say leaves the model before actions[], so the viewer hears "On it." or "Let me look." while the command or tool is still on its way.

awaited, inside the turn fired, never awaited memory injected into context

Why the loop is bounded. A voice interface cannot afford an open-ended tool loop. Cycle 1 always speaks something; only an internal tool result earns cycle 2, and cycle 2 has 1.2 s to produce its first spoken byte before render_fallback speaks the results from a template. Internal verbs emitted in cycle 2 are ignored. Every tool call, TV or internal, sits under a 400 ms timeout and degrades to a status the model can talk about.

Two command classes, one vocabulary. The twelve verbs are Pydantic models; the prompt's capability manifest, the JSON envelope schema and the TV app's types are all generated from them. Item commands carry a title_id the model copied from the Screen section or from a recommendation; the bus validates and enqueues but never resolves. search_catalog is the only verb that blocks the turn for a result.

Three stores, kept apart. The catalog and its embeddings never enter memory. Watch history is behavioural: it becomes the taste vector, the never-watched filter and the "Recently watched / recommended" prompt line. VoiceMem holds only what the viewer said — stated preferences and persona — which is exactly the signal collaborative filtering cannot see, and which the model turns into exclude_genres. Screen state is per-turn context and reaches none of them.

What changed since v1.

  • The "TV control tools" layer with deixis resolution and stale-seq retry does not exist as code. Resolution happens in the model against the Screen tiles; the bus validates; there is no seq or stale retry.
  • Memory ingest moved from a frame tap into the agent, so an interrupted reply is remembered with exactly what was said.
  • Recommendations are an internal tool with typed TMDB genre constraints, not an inline step; the query embedding is warmed from the same STT partial as the memory prefetch.
  • A history store was added and feeds both the prompt and the recommender.
  • Providers are pinned: SmallWebRTC, Silero VAD, Deepgram Nova 3 and Cartesia Sonic 3 on SLNG, Qwen3-30B on Nebius, Anam cara-4. VoiceMem runs on a local E5 with English-patched notes.
