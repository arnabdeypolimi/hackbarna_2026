TV buddy v3: planes, the bounded agent loop, the rolling profile, the trace tree

Media rides WebRTC across the top and back. Control rides its own WebSocket. One Pipecat pipeline per session; the agent is a Pipecat LLMService that streams one strict JSON envelope per cycle, speaks say sentence by sentence while actions[] dispatch in parallel, and runs a bounded loop — AGENT_MAX_CYCLES round trips, every follow-up cycle on a first-byte budget with a templated answer behind it. Everything that can wait — the memory ingest, the profile fold, history writes, status events, spans — is fired and never awaited.

SGRAgentService._turn assembles the prompt and hands the cycles to TurnRunner.run: recall, prompt, cycle 1, then a follow-up cycle for every tool result that earns one, up to AGENT_MAX_CYCLES. say leaves the model before actions[], so the viewer hears “On it.” or “Let me look.” while the command or the tool is still on its way — there is no canned filler any more.

The same turn, as one trace

OpenTelemetry is the only instrumentation API; Langfuse is an OTLP/HTTP sink, never an SDK. Pipecat emits conversation → turn → stt / tts; everything of ours hangs underneath through one observation() helper, so no span can forget to declare its Langfuse type. Off by default, and never on the media path: a span is an attribute write, export is batched on a background thread.

an LLM call — priced and token-counted in Langfuse outside the turn's tree

Why the loop is bounded. A voice interface cannot afford an open-ended tool loop. Cycle 1 always speaks something. A follow-up cycle happens only when a cycle produced an observation — an internal tool's reply, or any awaited action that failed — and it has CYCLE_FIRST_BYTE_S (1.2 s) to produce its first spoken byte before render_fallback speaks the results from a template. The last allowed cycle is decoded against a schema whose actions union has no internal tools, so the model cannot ask for more and the loop always ends in speech — the cap is the schema's, not a runtime guard. AGENT_MAX_CYCLES is a setting (1–4, default 2), not a hand-unrolled second cycle: each extra cycle is a full round trip the viewer hears as waiting.

One registry, two kinds of action. agent/envelope.py holds one ActionSpec per verb — TV or internal, whether the turn blocks on the reply, whether that reply is an observation the model must see, and how the prompt's capability manifest describes it. The envelope's actions[] union, the JSON Schema used for constrained decoding, the manifest and the TV app's TypeScript all derive from it, and dispatch matches on the parsed union member rather than on a verb string. Item commands carry a title_id the model copied from # Screen, # Recent activity or a recommendation; the bus validates and enqueues but never resolves.

Three stores, kept apart. The catalog and its embeddings never enter memory. The viewing log is behavioural: it becomes the taste vector, the never-watched and never-declined filters, and the # Recent activity lines — with ids, which is what makes “yes, play it” work for a title that is not on screen. The profile holds only what the viewer is like, and the summariser is told the TV keeps its own log, so a stray line can shade the tone but never pick the film. Screen state is per-turn context and reaches neither.

What changed since v2 (that diagram was drawn before the agent cleanup, d13428f..7aa8f13, and before observability):

  • Memory is one rolling profile, not VoiceMem. No left brain / right brain, no top-5 memory search, no local E5 for memory. SummaryMemoryLane appends every exchange to pending.jsonl and one LLM call rewrites profile.md — at session end and every 6 ingests, so what was said in turn 1 is back in the prompt by turn 7 even though the conversation window is ~5 exchanges.
  • recall_memory is gone. With a rolling profile it could only return what # Memory already held, and it bought a ~1 s second cycle for nothing.
  • The agent is the sole writer of the system prompt. ScreenContextInjector used to stamp # Screen and # Recent activity and then build_messages appended them again — two fetches and two copies per turn. The injector is now wired only for AGENT_IMPL=stub.
  • rec_shown moved to turn end and records what the agent actually named or focused, not the ≤ 8 titles the tool returned. An interrupted turn records nothing, and the greeting can no longer offer a film the viewer never heard.
  • The canned TTFT filler was deleted. It was off in production and cost a task, a race and a finally; the model's own first sentence is the filler.
  • A failed awaited TV command now earns a cycle. Seen live with no TV attached: the filler “Searching for X.” was the whole turn and the viewer waited on nothing.
  • An echo filter exists, and is off by default. Browser AEC leaves the avatar's own sentences intelligible enough that Safari and Chrome both returned them as user transcripts; VAD thresholds cannot tell them apart, but the text can — a “user” utterance that repeats ≥ 60 % of what the avatar just said, while echo is still physically possible, is echo. The catch is that short corrections reuse those words: “no, die hard” right after the avatar named No Hard Feelings was dropped too. So ECHO_FILTER=false, and barge-in leans on browser AEC plus the two-transcribed-word threshold instead.
  • Embeddings are local by default — multilingual-e5-small, 384 dims, ~15 ms per query. Cloud Qwen3-Embedding-8B measured 200–500 ms and blew the 400 ms tool budget in the field.
  • Tracing exists (third panel), and is off by default.
